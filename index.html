소개

“고객의 요구를 서비스로 연결해 온 PM입니다.”
요구사항을 그대로 전달하지 않고 실제 업무 목적을 확인한 뒤, 개발 조직과 구현 가능 범위·우선순위를 협의해 프로젝트를 오픈까지 끌고 갑니다.

- 다양한 산업군의 약 20개 고객사·프로젝트에서 요구사항 분석, 일정·이슈 관리, 고객사 협의, 내부 개발팀 조율까지 프로젝트 전반을 담당했습니다. 동시 진행 최대 [O]건을 관리하며 [납기 준수율 / 재계약 등 결과 수치]를 달성했습니다.

- 스타트업 초기 멤버로 합류해 정립되지 않았던 업무를 매뉴얼로 표준화하고, 축적된 업무 지식을 업무 관리·QA·착수 산출물 시스템 3종으로 시스템화했습니다. 요구 정의·설계·검증은 직접 하고 구현은 AI 개발 도구를 활용해, 기획자가 문제를 정의하고 해결까지 완결할 수 있음을 확인했습니다.

- 입사 [O]년차에 부팀장을 맡아 실무 PM과 병행하여 구성원의 업무 배분·일정 조율·진행 상황 점검을 담당하고 있습니다.

프로젝트

  • [양천해누리복지관] 그룹웨어 및 AI 활용 기능 구축
    (주)제로스트에이아이PM · 요구정의 / 일정 / 고객 협의 / QA
    2026.06 ~ 진행 중

    문제점
    장애인 활동지원 서비스를 운영하는 복지관이 이용자·활동지원사 관리, 상담일지, 세입세출 회계, 실적 집계를 수기·엑셀·구글폼 등으로 분산 관리. 계약 범위는 기능 16종 + AI 기능 3종(매칭 추천 · 음성→상담일지 · 내부 DB 연동 챗봇)으로, 사회복지 회계(관·항·목·세목, 수입·지출 결의서, 현금출납부)와 바우처 부정수급 모니터링 등 처음 접하는 업무 도메인.

    해결
    계약서에서 기능 정의서 → 페이지 맵 → 화면 시안을 개발 착수 전에 제작해 고객이 실제 화면을 보고 검토하도록 함. 고객이 시안 화면에 직접 코멘트를 남기는 리뷰 루프를 운영해 요청 [O]건을 반영/추가비용/협의 항목으로 분류·처리. 관리자 화면 5종의 사용자 화면 이전, 업무일지 삭제, 예산대비집행현황 추가 등 계약 범위와 다른 요청은 기능 리스트와 대조해 협의 항목으로 분리하고 반영 확인서로 확정. 결의서 출력 서식을 고객사 PDF 기준으로 표준화, 테스트케이스 [O]건으로 검증.

    성과

    • 개발 착수 전 화면 시안 단계에서 고객 피드백 [O]건 반영 → 개발 중 재작업 [감소 수치]
    • 기획서 피드백 반영 확인서 체결로 범위 확정

  • PM Station — 업무 관리 시스템 구축
    사내 시스템기획 / 설계 / 운영
    [YYYY.MM] ~ 운영 중

    문제점
    정기 업무와 프로젝트별 To-do, 회의록, 고객사 수신 대기 자료가 메신저·문서·개인 메모에 흩어져 누락과 중복 확인이 반복됨.

    해결
    업무 흐름을 먼저 분석해 차수(1차·2차) 단위로 진척·이슈·후속조치·수신 대기 자료를 한 화면에서 관리하는 구조를 설계. AI 개발 도구로 구현해 Microsoft Teams와 연동, 정기 업무·To-do를 지정 시점에 자동 알림. 축적된 업무 매뉴얼을 챗봇에 연결해 문서 검색 대신 자연어로 질의.

    성과

    • 약 20개 고객사·프로젝트의 진척·이슈를 단일 화면에서 관리, [누락 건수 / 확인 시간 감소 수치]
    • Supabase · PostgreSQL · React · PWA
  • QA Station — 테스트케이스·결함 관리 시스템
    사내 시스템프로세스 설계
    [YYYY.MM] ~ 운영 중

    문제점
    “고쳤다고 했는데 안 고쳐진” 결함이 메신저 대화 속에서 조용히 사라지고, 배포 회차별 테스트 진행도를 집계할 방법이 없었음.

    해결
    테스트케이스 등록(엑셀 붙여넣기) → 배포 회차별 실행 체크 → 진행도 자동 집계 구조를 설계. 결함 상태(신규·정보요청·수정중·수정완료·재발·검증완료)로 “지금 누구 차례인지”를 항상 확정하고, 개발은 수정완료까지만·닫는 것은 QA의 검증완료로 규칙화.

    성과

    • 결함 왕복 이력이 남아 재발 결함 추적 가능, 마크다운 리포트로 개발팀 전달 표준화
    • [테스트케이스 O건 / 결함 O건 처리 수치]
  • PRD Toolkit — 착수 산출물 표준화 파이프라인
    사내 시스템프로세스 설계
    [YYYY.MM] ~ 운영 중

    문제점
    계약 후 착수 산출물(기능 정의·화면 설계)이 담당자 개인 경험에 따라 형식과 깊이가 달라, 고객 검토가 개발 중반에야 이뤄지고 재작업이 발생.

    해결
    계약서 → 기능 정의서 → 페이지 맵 → 디자인 토큰 기반 화면 시안 → 고객 공유 문서까지를 단계별 규칙으로 표준화. 고객 코멘트를 산출물에 되먹이는 리뷰 루프를 포함해 검토 시점을 개발 착수 전으로 앞당김.

    성과

    • 양천해누리복지관 건에 적용, 시안 단계에서 고객 피드백 [O]건 반영
    • 기능정의서 · 페이지맵 · 화면 시안 · 검토 문서
