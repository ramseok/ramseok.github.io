고객의 요구를 서비스로 연결해 온 PM입니다.

다양한 산업군의 SI 프로젝트를 수행하며 고객 요구사항을 분석하고, 이를 실제 서비스와 기능으로 구현할 수 있도록 고객사와 내부 개발 조직을 연결해 왔습니다. 요구사항 분석 · 일정 관리 · 이슈 대응 · 개발팀 조율까지 프로젝트 전반을 담당했고, 업무 과정에서 발견한 비효율은 프로세스로 표준화한 뒤 업무 시스템으로 만들어 왔습니다.

①

SI 프로젝트 관리

[00]개 고객사·프로젝트에서 착수부터 오픈까지 일정 · 이슈 · 산출물을 관리했습니다.

②

요구사항 분석 및 조율

요구사항을 그대로 전달하지 않고 실제 업무 목적을 확인한 뒤, 개발팀과 구현 가능 여부 및 우선순위를 협의했습니다.

③

산업·업무에 대한 빠른 이해

프로젝트마다 업무 프로세스가 달랐기 때문에, 새로운 도메인을 짧은 시간에 구조화하는 방법을 갖췄습니다.

④

프로세스 설계 → 시스템화

반복 업무를 매뉴얼로 표준화하고, 축적된 업무 지식을 업무 관리 시스템으로 연결했습니다.

⑤

리더십

실무 PM과 병행해 부팀장으로서 구성원의 업무 배분 · 일정 조율 · 진행 상황 점검을 담당했습니다.

03 — Systems Built

구축한 업무 시스템

도구를 써 본 경험이 아니라, 업무에서 발생한 문제를 먼저 정의하고 해결 방식을 설계한 결과입니다. 요구 정의 · 설계 · 검증은 직접 했고, 구현은 AI 개발 도구를 활용했습니다.

PM Station

업무 관리 시스템 · 기획 / 설계 / 운영

정기 업무와 프로젝트별 To-do, 회의록이 여러 곳에 흩어져 발생하던 관리 비효율을 해결하기 위해 만든 PM 전용 도구.

  • 차수(1차·2차) 단위로 진척 · 이슈 · 후속조치 · 수신 대기 자료를 한 화면에서 관리
  • Microsoft Teams 연동 — 정기 업무와 To-do를 지정 시점에 자동 알림
  • 축적된 업무 매뉴얼을 챗봇에 연결해 자연어로 검색
Supabase · PostgreSQL · React · PWA

QA Station

QA 관리 시스템 · 프로세스 설계

“고쳤다고 했는데 안 고쳐진” 항목이 조용히 사라지지 않도록, 개발팀과 QA가 같은 화면에서 주고받게 만든 도구.

  • 테스트케이스 등록(엑셀 붙여넣기) → 배포 회차별 실행 체크 → 진행도 자동 집계
  • 결함 상태로 “지금 누구 차례인지”를 항상 확정
  • 개발은 수정완료까지만, 닫는 것은 QA의 검증완료
테스트케이스 · 결함 왕복 · 마크다운 리포트

PRD Toolkit

착수 산출물 표준화 · 파이프라인 설계

계약서에서 기능 정의 → 페이지 맵 → 화면 시안 → 고객 공유 문서까지, 프로젝트 착수 산출물을 같은 기준으로 만들도록 정리한 작업 체계.

  • 개인 경험에 의존하던 착수 산출물을 단계별 규칙으로 표준화
  • 디자인 토큰 기반의 화면 시안으로 고객 검토 시점을 앞당김
  • 고객 코멘트를 산출물에 되먹이는 리뷰 루프
기능정의서 · 페이지맵 · 화면 시안 · 검토 문서

04 — How I Work

일하는 방식

요구가 접수되고 오픈되기까지, 프로젝트마다 같은 순서를 지킵니다.

01

요구 접수

요청받은 문장을 그대로 기록합니다. 이 시점에는 해석하지 않습니다.

02

목적 확인

“그 기능으로 어떤 업무를 처리하려 하는가”를 확인해 요구의 진짜 목적을 분리합니다.

03

범위·우선순위 협의

개발팀과 구현 가능 여부·공수를 확인하고, 고객과 범위와 일정을 합의합니다.

04

산출물 확정

기능 정의와 화면 설계로 문서화해, 양측이 같은 것을 보고 있는지 맞춥니다.

05

개발 조율 · 이슈 관리

진행 중 발생하는 변경과 결함을 “누구 차례인지”가 항상 분명한 상태로 관리합니다.

06

검증 · 오픈

테스트케이스 기준으로 검증하고, 남은 항목은 합의된 상태로 종료합니다.
