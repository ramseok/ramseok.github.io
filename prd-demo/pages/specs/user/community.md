# P22 커뮤니티

> URL `/community` · 대상 **사용자** · 관련 기능 F22 · 계약서 우선순위 **P2(고도화)**

비슷한 상실을 겪은 보호자들이 경험을 나누는 익명 게시판이다. "마음 돌봄" 메뉴 안에서 아티클·상담(P21)과 탭으로 묶여 있으며, 사용자는 목록에서 글을 훑어보고, 상세를 열어 댓글을 달고, 직접 글을 쓰거나, 부적절한 글·댓글을 신고할 수 있다. 신고된 글의 실제 숨김·삭제·제재는 이 화면이 아니라 관리자 신고·모더레이션 화면(P32, F42)에서 처리된다.

## 동작 정의

### 1. 게시글 목록·상세 열람 (F22)

1. 화면 진입 시 더미 게시글 7건이 최신순으로 나열되고 "전체 7개" 카운트가 표시된다.
2. 게시글 카드의 제목·요약 영역을 누르면 바텀시트로 상세가 열리고 작성자·시간, 본문 전체, 댓글 목록, 공감 수, 댓글 수가 표시된다.
3. 상세 시트를 열 때마다 해당 카드의 최신 공감 수·댓글 수를 그대로 반영한다.
4. 카드 우측 상단 또는 상세 시트 상단의 깃발 아이콘은 목록 클릭과 별도 영역으로 분리되어 있어, 깃발을 눌러도 상세가 열리지 않고 신고 시트가 뜬다.

### 2. 공감(좋아요) 토글 (F22)

1. 목록 카드의 하트 칩을 누르면 칩이 강조 스타일로 바뀌고 공감 수가 1 증가한다.
2. 같은 칩을 다시 누르면 강조가 풀리고 공감 수가 원래 값으로 돌아간다.
3. 상세 바텀시트에는 별도의 공감 버튼이 없고, 목록에서 누른 결과 값만 읽기 전용으로 표시된다.
4. 공감 상태는 새로고침하면 초기화된다 — 시안 한정으로 클라이언트 메모리에만 유지된다.

### 3. 댓글 작성 (F22)

1. 상세 시트 하단 입력창에 댓글을 적지 않고 "등록"을 누르면 입력창 테두리만 붉게 표시되고 등록되지 않는다.
2. 댓글을 입력하고 "등록"을 누르면 작성자 "나" · "방금 전"으로 댓글이 목록 맨 아래에 추가되고, 카드의 댓글 수가 1 증가하며, "댓글이 등록됐어요" 토스트가 뜬다.
3. 등록한 댓글에도 신고 아이콘이 함께 붙어 다른 댓글과 동일하게 신고할 수 있다.
4. 같은 시트를 닫았다가 다시 열어도(같은 세션 내) 방금 등록한 댓글은 유지된다.

### 4. 글쓰기 (F22)

1. 우측 하단 "글쓰기" 버튼을 누르면 "경험을 나눠주세요" 제목의 입력 바텀시트가 빈 입력칸으로 열리고, 상단에 "상업적 홍보나 판매 글은 안내 없이 숨김 처리될 수 있다"는 정책 배너가 표시된다.
2. 제목(최대 40자)·내용 중 하나라도 비운 채 "등록하기"를 누르면 "제목과 내용을 모두 적어주세요" 오류 문구가 노출되고 등록되지 않는다.
3. 둘 다 입력 후 등록하면 작성자 "나" · "방금 전 · 경험 공유"로 새 게시글이 목록 맨 위에 추가되고 "게시글이 등록됐어요" 토스트가 뜬다.
4. 새로 등록된 글도 공감·상세 열람·신고가 기존 글과 동일하게 동작한다(이벤트 위임 처리).
5. 시안에서는 새 글을 등록해도 "전체 N개" 카운트는 갱신되지 않는다 — 개발 반영 시 등록 즉시 카운트를 갱신해야 한다.

### 5. 신고 — 게시글·댓글 공통 (F22, F42)

1. 게시글 카드의 깃발 아이콘, 상세 시트 상단 깃발 아이콘 중 어느 쪽을 눌러도 "게시글 신고" 바텀시트가 열린다.
2. 댓글 옆 깃발 아이콘을 누르면 "댓글 신고" 바텀시트가 열린다.
3. 신고 사유 칩 4종 중 하나를 반드시 선택해야 하며, 선택 없이 "신고 접수하기"를 누르면 "신고 사유를 선택해 주세요" 오류가 표시된다.
4. "자세한 내용" 입력은 선택 사항(라벨 우측 "선택" 표시)이라 비워도 접수된다.
5. 접수하면 시트가 닫히고 "신고가 접수됐어요. 검토 후 처리할게요" 토스트가 뜨며, 신고에 사용한 깃발 버튼이 체크 아이콘으로 바뀌고 비활성화되어 같은 대상은 재신고할 수 없다.
6. 신고 접수만으로는 해당 게시글·댓글이 화면에서 숨겨지지 않는다. 실제 숨김·삭제·작성자 제재는 관리자 신고·모더레이션 화면(P32, F42)에서 운영자가 신고 사유를 검토한 뒤 처리하는 별도 절차다 — 이 검토·제재 판단을 수행할 모더레이션 담당 인력 배정이 필요하다.

## 상태·예외

| 상황 | 화면 처리 |
|------|-----------|
| 신고 사유 미선택 후 접수 시도 | 오류 문구 표시, 시트 유지 |
| 이미 신고한 게시글/댓글 재신고 시도 | 깃발 버튼이 체크 아이콘으로 비활성화되어 있어 재클릭 불가 |
| 게시글/댓글 없음(빈 상태) | 시안에는 없음 — 더미 7건이 항상 고정 표시됨 |
| 공감·댓글·신고·새 글 상태 | 새로고침 시 전부 초기화(시안 한정), 개발 반영 시 서버에 저장해 유지해야 한다 |
| 게시글 카테고리 | 전부 "경험 공유" 고정 표기, 카테고리 선택 UI는 없음 |
| 글자 크기 저장값(lg/xl) 있음 | P8에서 고른 크기로 화면 전체 글자 확대 |

## 확정 필요

- 계약서상 F22는 우선순위 **P2(고도화)** 항목으로 표기되어 있어 정식 개발 착수 시점(1차 출시 포함 여부)을 재확인해야 한다.
- F22 정의에는 "글을 작성·수정·삭제한다"가 있으나 시안에는 등록 UI만 있고 본인 글 수정·삭제 UI가 없다 — 제공 범위 확정 필요.
- 신고 접수 건을 실제로 검토·처리할 모더레이션 운영 인력의 배치 여부와 처리 SLA(예: 며칠 내 검토) 확정 필요.
- 상업 홍보 글에 대한 자동 필터링(키워드 차단 등) 도입 여부 — 시안은 안내 문구 노출만 제공한다.
